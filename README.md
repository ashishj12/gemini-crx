# Relay — customer experience resolution

A production-structured, deployment-ready challenge PoC built from the supplied Topcoder telecom baseline. The customer workspace provides verified account answers, service diagnostics, explicit case confirmation and traceable human handoff. Separate role-protected Review Lab and Operations screens expose the actual scenario results and event-derived metrics.

**Stack:** Next.js App Router · TypeScript · Bun · FastAPI/Uvicorn · Pydantic · Google GenAI SDK · SQLite. Enterprise data is synthetic. Live Gemini verification and local scenario evidence are recorded separately. No demo video is included, as requested.

## Start locally

Requires Python 3.11+ (validated on 3.12), Bun 1.3.14 and internet access for dependency installation. Windows PowerShell, from this directory:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
bun install --frozen-lockfile
Copy-Item .env.example .env
.venv\Scripts\python.exe tools/dev.py
```

On macOS/Linux use `.venv/bin/python` and `cp .env.example .env`. Open **http://127.0.0.1:3000**. Ctrl+C shuts down the three processes created by the launcher. Use the same host consistently; cookies and origin validation are intentional. API documentation is available directly at http://127.0.0.1:8080/docs in Reviewer mode. Only the frontend should be exposed outside the workstation.

The sample-account menu supplies Alex Morgan (`alex.morgan` / `ReviewerPass-1001`), Jordan Lee (`jordan.lee` / `ReviewerPass-1002`) and the support user (`support.agent` / `ReviewerPass-3001`). These are public synthetic challenge credentials. The support user can run all eight scenarios and inspect operations/handoffs; customers cannot access those APIs.

For real inference, set `APP_MODE=LIVE_AI`, `GEMINI_MODEL` to a model available to your key and `GEMINI_API_KEY` in the ignored root `.env`, then restart. Reviewer requires no model access. Degraded mode preserves deterministic authorization and verified enterprise facts when Gemini fails. The key is used only by the API; it is absent from the client bundle and release archive.

## Project map

```text
apps/
  web/                 Next.js application, components, typed API client and same-origin gateway
  api/
    src/relay_api/
      domain/          Validated client, AI and enterprise data models

      http/            FastAPI transport and session boundary
      evaluation/      Executable challenge acceptance contracts
      core/            Safe configuration loading
services/mock-telecom/  Runnable supplied synthetic telecom integration service
resources/challenge/    Original contracts, fixtures, rubric and preserved starter provenance
tests/                 Acceptance, contract and integration tests
tools/                 Development, HTTP evaluation, auditing and safe release tooling
deployment/            Container definitions and Google Cloud deployment guidance

```

Generated dependencies, local secrets, databases, caches and archived earlier work stay ignored. No duplicated production server or alternate frontend is shipped. `resources/challenge/starter-solution` preserves the original baseline for review; it is not the runtime.

## Verify and package

```powershell
.venv\Scripts\python.exe -m pytest -q --junitxml=evidence/current/pytest.xml
.venv\Scripts\python.exe tools/evaluate.py --mode REVIEWER
.venv\Scripts\python.exe tools/evaluate.py --mode LIVE_AI --output evidence/current/live-gemini-evidence.json
bun run typecheck
bun run test:web
bun run build
.venv\Scripts\python.exe tools/compliance_audit.py
.venv\Scripts\python.exe tools/package_release.py
```

Live verification makes genuine provider calls and may encounter quotas or degraded fallback. It exits nonzero unless all required live stages succeed. No key is necessary for pytest, Reviewer, type checking or building. The source ZIP and SHA-256 checksum are written to `release/`. The packager scans the exact files for the configured secret, rejects unexpected binary/runtime files and emits a per-file hash manifest.

## Containers and Google Cloud

`docker compose up --build` starts Next.js, the private API and private synthetic telecom service. It persists state in the `cx-data` volume. `docker compose down` preserves that data; do not remove the volume if pending actions matter. Set `.env` before starting, especially the exact public origin. See [deployment guidance](deployment/README.md) for the single-instance Compute Engine path and Cloud Run migration boundary.

See [architecture](docs/ARCHITECTURE.md), [Gemini invocations](docs/GEMINI_INVOCATIONS.md), [security](docs/SECURITY.md), [handover](docs/HANDOVER.md), [changes and design](docs/CHANGES.md), and the [source-referenced compliance audit](docs/FINAL_COMPLIANCE_AUDIT.md).

The challenge permits a controlled AI-assisted workflow; this implementation has one orchestrator and bounded AI stages. Synthetic authentication and telecom services do not constitute a certified production CSP platform. GCP deployment and independent qualification scoring are not claimed. The original rubric requires 75% overall and 70% in each of the first four categories; passing local tests does not establish those scores.
