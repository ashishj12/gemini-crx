# Changes and design decisions

The original supplied baseline remains under resources/challenge/starter-solution. Its insecure placeholder response flow is replaced by an authenticated, persistent workflow using the same supplied customer/account/service contracts and scenarios. Telecom fixtures and schemas remain inspectable; the runnable mock is isolated in services/mock-telecom. No unrelated dataset or business workflow is substituted.

The previous flat implementation has been split into a Python src package with HTTP, application, domain, AI and infrastructure boundaries. Tests are categorized by acceptance, contracts and integration. The API uses FastAPI/Uvicorn. Dependencies and runtime locks are separated from test tooling; video libraries and recordings are absent from the release. Tools, deployment configuration, immutable challenge inputs, execution evidence and documentation have dedicated homes.

The frontend is a new Next.js App Router/TypeScript application built with Bun. A same-origin server gateway keeps internal URLs and model credentials off the client. Customer support, authorized review and operations each have a focused view. Account details, metrics, traces, scenario checks and handoffs are loaded from actual APIs. Consequential actions have an explicit confirmation card. Errors, loading, no-data and provider fallback states remain visible. Session/history survives refresh.

Design reference: https://www.awwwards.com/ was inspected for editorial typography, confident whitespace and restrained composition. Relay uses a warm ivory background, charcoal navigation, sage accents, locally bundled Geist fonts, deliberate numbered sections and a concentric connection motif. The visual system supports support tasks instead of decorative scrolling. Responsive layouts, labeled controls, keyboard-native dialogs, text mode labels and reduced-motion styling support practical use. No Awwwards imagery or site assets are copied.

The Gemini adapter uses native JSON Schema output plus strict local Pydantic validation. This fixes the genuine provider rejection of the SDK-converted `additional_properties` field without weakening the forbid-extra contract. Actual credentialed runs are recorded separately from simulated reviewer tests. Provider timeout and rate-limit failures produce labeled degraded results; they are never counted as live success.

Remaining production work: enterprise identity federation, private enterprise gateways, managed transactional storage for replicas, external handoff delivery, retention/purge jobs, distributed rate limits, whole-workflow deadlines, monitoring exports and independent load/security/accessibility evaluation. Current serialized state mutation and persisted action claims support one API process. GCP configuration is prepared, not deployed. The demo video is explicitly excluded by the latest user request.
